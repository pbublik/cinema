# Проверка реализации — 14 ноября 2026

Исправление переходов по рекомендациям VK: событие `recommendationClicked` теперь восстанавливает iframe из ссылки комнаты; `inited` с идентификатором другого видео также вызывает восстановление. События старого экземпляра игнорируются, отложенные команды отменяются. Регрессионная проверка с тестовым API в Chrome и Firefox: клик ведущего и зрителя по рекомендации на паузе, запоздалый `started`, неожиданный `videoId`; исходная ссылка, позиция, пауза и версия состояния комнаты сохраняются. Реальные карточки рекомендаций VK в этой среде не проверялись из-за описанной ниже недоступности ролика.

Обновление CINEMA: увеличены шрифты, удалены вспомогательные подписи. Браузерные проверки дополнены плавающим полноэкранным чатом: три последних сообщения, отправка из мини-чата, переключение в полную историю, скрытие/показ, сохранение единственного iframe и размещение панели в мобильном окне. Оба браузера прошли эти проверки. Подготовлена конфигурация Render Free, но публикация и проверка на хостинге не выполнялись.

Реализованы клиент и сервер. **Полная приёмка по `tech.md` ещё не завершена**: реальный VK-плеер вернул недоступность видео, Windows 7 и двухчасовой просмотр не проверены.

## Реальный VK

Проверялась ссылка пользователя `https://vkvideo.ru/video-121898133_456247731`, варианты встраивания через `vk.com` / `vkvideo.ru`, а затем точный адрес из кода экспорта:

```text
https://vk.ru/video_ext.php?oid=-121898133&id=456247731&hash=01643e57e4a2f464&js_api=1
```

VK показал «Видео недоступно» в обоих чистых браузерных профилях. Причина (права, доступность ролика, сетевые/региональные условия) по этому ответу не определена. Скриншоты `vk-chromium.png`, `vk-firefox.png` и `vk-probe.json` сохраняют наблюдение. Официальный API был доступен; использованы его фактические методы `play`, `pause`, `seek`, `getCurrentTime`, `getState`, `destroy` и события `inited`, `started`, `resumed`, `paused`, `seeked`, `ended`, `error`, `adStarted`, `adCompleted`, `autoplaySoundProhibited`.

Пока на реальном доступном ролике не проверены: программное управление, точность синхронизации, буферизация, реклама, ограничения autoplay, работа самого видео после fullscreen. В реализации есть обработчики этих ситуаций, но это не заменяет испытания.

## Оставшаяся приёмка

1. На трёх устройствах/профилях открыть доступный встраиваемый VK-ролик. Проверить запуск, паузу и перемотку кнопками сайта и внутри iframe ведущего. Измерить расхождение после синхронизации: целевое значение ≤ 1,5 с.
2. Подключить зрителя во время воспроизведения, проверить отставание после буферизации, рекламу, ручной Play и ручную синхронизацию. Проверить смену видео несколько раз и отсутствие накопления iframe/обработчиков.
3. Отключить ведущего меньше чем на 60 секунд, вернуть; затем отключить более чем на 60 секунд и проверить преемника. Протокольная логика уже проверена автоматически с управляемыми часами.
4. Провести **непрерывный двухчасовой просмотр** в трёх браузерах, измеряя память браузеров и сервера, дубли событий и количество соединений. Подготовлен отдельный двухчасовой серверный прогон `npm.cmd run test:soak`, но он не воспроизводит VK и не заменяет браузерное испытание. Для короткой проверки: `$env:SOAK_SECONDS='60'; npm.cmd run test:soak`. Перед полным запуском удалить переменную: `Remove-Item Env:SOAK_SECONDS -ErrorAction SilentlyContinue`.
5. На Windows 7 проверить Chrome 109 и Firefox 115 ESR по адресу с `?legacy=1`. Отдельно записать работоспособность интерфейса, чата и VK/кодеков. Сборка для этих версий имеется; реальные испытания не проведены.
6. На слабом компьютере проверить ввод и управление при 480p, указать CPU/RAM/GPU, версии ОС/браузера, измерения отзывчивости и расхода памяти. Текущая машина не считается целевым слабым компьютером.

Ссылка на комнату даёт гостевой доступ. Данные переживают штатный перезапуск одного сервера; отказоустойчивый кластер и восстановление личности на другом устройстве не реализованы и не входят в выбранную архитектуру.
