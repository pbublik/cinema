# Бесплатное размещение CINEMA

Проверено по документации провайдеров 14 ноября 2026 года. Сайт требует работающий Node.js-сервер с WebSocket. Видео передаётся из VK непосредственно зрителям; хостинг обслуживает только страницу, чат и синхронизацию.

## Рекомендация: Render Free

Для нескольких друзей и просмотра раз в неделю это простой вариант без изменения серверного кода. Поддерживаются Node.js, HTTPS и WebSocket. Сервис засыпает после 15 минут без входящих HTTP-запросов или WebSocket-сообщений; первый запуск после сна занимает примерно минуту. Клиент CINEMA отправляет WebSocket ping каждые 5 секунд, поэтому активная комната создаёт входящий трафик. Закрывайте вкладки после сеанса.

**Ограничение:** файлы бесплатного сервера исчезают при сне, перезапуске или деплое. Текущий `data/state.json` хранит комнаты, чат и гостевые сессии, поэтому старые приглашения и история могут перестать работать. Практичный сценарий: перед каждым просмотром открыть главную, создать новую комнату и разослать новое приглашение. Это допустимо для еженедельных сеансов, но не подходит для постоянной истории. Рестарт провайдера во время сеанса также потребует создать комнату заново.

У Free есть общий лимит 750 часов работы в месяц на workspace, а также ограничения трафика и сборок. Другие сервисы в том же аккаунте расходуют общие лимиты. Для одного еженедельного сеанса нагрузка сервера невелика, поскольку сам фильм через него не передаётся. Это оценка по архитектуре, а не гарантия доступности бесплатного тарифа.

### Настройка через панель Render

1. Создать репозиторий GitHub и загрузить исходники проекта, включая `package-lock.json`. Не добавлять `node_modules`, `data`, `dist`, `test-results` и `.env` — они уже перечислены в `.gitignore`.
2. На Render выбрать **New → Web Service**, подключить этот репозиторий.
3. Указать **Language: Node**, **Instance Type: Free**.
4. **Build Command:** `npm ci --include=dev && npm run build`.
5. **Start Command:** `npm start`.
6. Добавить переменные `NODE_VERSION=24.15.0` и `COOKIE_SECURE=1`. `HOST` можно не задавать: сервер слушает `0.0.0.0`; `PORT` задаёт Render автоматически.
7. Создать сервис. Он получит HTTPS-адрес вида `https://cinema-xxxx.onrender.com`.
8. При желании задать `PUBLIC_ORIGIN` равным точному выданному адресу без завершающего `/`. После этого подождать перезапуска.
9. Открыть главную, создать комнату, отправить приглашение друзьям. Проверить встраивание VK с устройств зрителей. Размещение на Render само по себе не устраняет ограничения доступа VK.

В репозитории также подготовлен `render.yaml`: можно выбрать **New → Blueprint** и подключить репозиторий, чтобы взять эти настройки из файла. Публикация не выполнялась.

Источники: [бесплатный тариф](https://render.com/docs/free), [настройка Web Service](https://render.com/docs/web-services), [WebSocket](https://render.com/docs/websocket).

## Альтернатива: Koyeb Free

Koyeb предоставляет один Free instance: 512 МБ RAM, 0,1 vCPU и 2 ГБ SSD. Он засыпает после часа простоя; бесплатные экземпляры не поддерживают постоянные Volumes. Для небольшой комнаты ресурсов предположительно достаточно, однако проблемы сохранения данных остаются. Условия регистрации и доступные регионы следует проверить в аккаунте. Источники: [Free instance](https://www.koyeb.com/docs/reference/instances), [Scale-to-Zero](https://www.koyeb.com/docs/run-and-scale/scale-to-zero).

## Если нужны постоянные комнаты

Потребуется изменить хранение: перенести комнаты, сообщения и хеши сессий из локального JSON во внешнюю базу данных либо выбрать сервер с постоянным диском. Только подключить базу в панели провайдера недостаточно — текущий код сам ею пользоваться не начнёт. Для сеансов раз в неделю проще начать с новой комнаты при каждом просмотре.
