**Техническое задание: сайт для совместного просмотра VK Видео**

**1. Назначение**

Создать лёгкий сайт для совместного просмотра VK Видео в комнате по ссылке. Основной сценарий — три человека одновременно смотрят видео и общаются в текстовом чате.

Видео загружается каждому зрителю непосредственно из VK. Сервер сайта обслуживает комнаты, сообщения и синхронизацию воспроизведения.

**2. Вход по никнейму**

- При первом входе пользователь вводит только никнейм.
- Пароль, электронная почта, телефон и авторизация через социальные сети не требуются.
- Никнейм: от 2 до 24 символов. Поддерживаются кириллица и латиница.
- Никнейм сохраняется в браузере.
- Пользователь получает случайный идентификатор сессии. Никнейм используется для отображения, идентификатор — для определения участника и его прав.
- Одинаковые никнеймы внутри одной комнаты не допускаются.
- После обновления страницы пользователь по возможности возвращается в комнату с прежним именем и ролью.

Вход является гостевым: восстановление личности на другом устройстве не предусматривается.

**3. Комната**

- Пользователь может создать комнату и скопировать ссылку-приглашение.
- Присоединиться может любой человек, имеющий ссылку, после ввода никнейма.
- Адрес комнаты содержит длинный случайный идентификатор.
- Создатель комнаты становится ведущим.
- Отображаются список участников и состояние подключения.
- Ведущий может передать управление другому участнику.
- При отключении ведущего его роль сохраняется за ним 60 секунд. Затем ведущим становится наиболее давно подключённый участник.
- Права ведущего проверяются сервером.

**4. Интерфейс**

На компьютере:

- Основная область слева — видеоплеер.
- Справа — чат шириной приблизительно 300–360 пикселей.
- Над плеером — поле ссылки VK Видео и кнопка «Открыть», доступные ведущему.
- Рядом — название комнаты, список участников и кнопка «Скопировать приглашение».
- Под плеером — состояние синхронизации, кнопки «Синхронизироваться» и «Полный экран».

На узком экране чат переносится под видео. Интерфейс должен помещаться на экране 1366 × 768 без горизонтальной прокрутки.

Оформление: тёмный фон, контрастный текст, простые кнопки, минимум декоративных эффектов.

**5. Синхронизация VK Видео**

Ведущий выбирает видео и управляет общим воспроизведением:

- запуск;
- пауза;
- перемотка;
- смена видео.

Действия ведущего передаются всем участникам. Громкость и качество изображения каждый зритель выбирает самостоятельно.

Сервер хранит общее состояние: видео, позицию, статус воспроизведения, время обновления и номер версии состояния. При расчёте текущей позиции учитывается время, прошедшее после команды ведущего.

Новый участник подключается к актуальному моменту просмотра. После потери соединения браузер запрашивает текущее состояние комнаты.

Предусмотреть:

- проверку расхождения примерно раз в 5 секунд;
- корректировку при расхождении более 1,5–2 секунд;
- кнопку ручной синхронизации;
- защиту от циклической отправки событий при программной перемотке;
- отклонение устаревших команд;
- уведомление, если браузер требует вручную нажать Play.

При буферизации отдельного зрителя остальные продолжают просмотр. После загрузки отставший зритель возвращается к общей позиции.

Целевое расхождение при стабильном соединении — не более 1,5 секунды после завершения синхронизации. Это проверяется на реальном плеере; покадровая синхронность не требуется.

**6. Особенности интеграции с VK**

Использовать официальный встроенный плеер и доступный интерфейс управления.

До разработки полноценного интерфейса сделать техническую проверку в двух браузерах:

- встраивание видео;
- программный запуск и пауза;
- перемотка;
- получение позиции и событий воспроизведения;
- работа после перехода в полный экран.

Поддержать обычные публичные ссылки `vk.com` и `vkvideo.ru`, для которых доступно встраивание. Проверять введённый адрес; произвольный HTML пользователя не исполнять.

Если видео закрыто, недоступно или не поддерживает встраивание, показывать понятное сообщение.

Отдельно проверить поведение во время рекламы. При наличии соответствующих событий плеера учитывать их и синхронизировать просмотр после окончания рекламы. Если плеер не предоставляет необходимых событий, обозначить ограничение и оставить ручную синхронизацию.

**7. Чат справа**

Сообщения отображаются в формате:

**Никнейм · 21:35**  
Текст сообщения.

Требования:

- доставка сообщений без обновления страницы;
- время отправки определяется сервером и отображается в часовом поясе зрителя;
- отправка по Enter;
- перенос строки по Shift + Enter;
- отдельная кнопка «Отправить»;
- длина сообщения — до 2000 символов;
- пустые сообщения не отправляются;
- сообщения отображаются как безопасный текст, без исполнения HTML;
- автопрокрутка работает, если пользователь находится внизу чата;
- при чтении старых сообщений новые не сбрасывают положение прокрутки;
- появляется индикатор новых сообщений;
- системные уведомления о входе, выходе и смене ведущего.

Хранить последние 200 сообщений комнаты. При подключении загружать последние 50, остальные — по запросу. Добавить ограничение частоты отправки для защиты от случайного спама.

**8. Полноэкранный режим**

Кнопка «Полный экран» разворачивает область просмотра на весь экран.

- По умолчанию видео занимает всё доступное пространство, чат скрыт.
- Кнопка «Чат» позволяет показать или скрыть боковую панель.
- Выход — по Escape или повторному нажатию кнопки.
- Состояние просмотра и соединение с комнатой сохраняются.
- Использовать Fullscreen API, где он доступен.
- Если браузер не поддерживает необходимый режим, разворачивать область просмотра в пределах окна.

Полноэкранный режим сайта с чатом реализуется отдельно от встроенной кнопки полного экрана VK.

**9. Производительность и старые компьютеры**

Сайт должен создавать минимальную дополнительную нагрузку поверх видеоплеера.

Требования:

- интерфейс на стандартных HTML и CSS, минимум JavaScript;
- без тяжёлых UI-библиотек, фонового видео, WebGL, размытия и постоянных анимаций;
- системные шрифты;
- один экземпляр видеоплеера;
- чат не должен перерисовывать плеер при поступлении сообщений;
- ограниченное количество сообщений в DOM;
- отсутствие постоянных высокочастотных проверок;
- обмен событиями через WebSocket;
- повторное подключение с увеличивающимся интервалом;
- отсутствие накопления обработчиков, таймеров и соединений;
- начальная загрузка собственных HTML, CSS и JavaScript — целевой объём до 300 КБ в сжатом виде, без ресурсов VK;
- для слабых устройств рекомендовать качество 360p или 480p через настройки плеера.

**10. Совместимость с Windows 7**

Предусмотреть отдельную совместимую сборку клиентского кода для проверки в Chrome 109 и Firefox 115 ESR под Windows 7.

- Транспилировать неподдерживаемый синтаксис.
- Добавлять только необходимые полифилы.
- Проверять доступность браузерных API перед использованием.
- Не делать критические функции зависимыми от новых возможностей браузеров.
- Для копирования приглашения предусмотреть запасной вариант: выделение ссылки и ручное копирование.

Совместимость оболочки сайта и воспроизведение VK проверяются отдельно. Работа VK Видео на Windows 7 зависит от самого плеера, браузера, кодеков и оборудования. Гарантировать её без испытания нельзя.

Если плеер не работает, сайт должен оставаться доступным и показывать понятную причину или сообщение о несовместимости.

**11. Проверка и критерии готовности**

Первая версия считается готовой после проверки:

1. Три человека входят в одну комнату по никнеймам.
2. Ведущий открывает доступное VK Видео.
3. Запуск, пауза и перемотка синхронизируются у участников.
4. Новый зритель подключается к текущей позиции.
5. После обновления страницы восстанавливаются сессия и состояние комнаты.
6. Чат показывает никнейм, текст и время; сообщения доставляются всем участникам.
7. Полный экран работает, чат можно показать и скрыть.
8. После кратковременного отключения интернета соединение восстанавливается.
9. Недоступные видео и ошибки загрузки сопровождаются понятными сообщениями.
10. Проведён непрерывный двухчасовой тест: отсутствуют дублирование событий и устойчивый рост памяти.
11. Проведены испытания на Windows 7 в указанных браузерах; отдельно зафиксированы работа интерфейса и работа VK-плеера.
12. На тестовом слабом компьютере ввод текста и управление интерфейсом остаются отзывчивыми при просмотре в 480p. Характеристики компьютера и результаты фиксируются в отчёте.
